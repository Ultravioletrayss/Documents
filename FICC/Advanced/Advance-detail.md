# 增强做市策略：设计思想与完整实现

---

## 第一章 策略定位与核心思想

### 1.1 什么是增强做市策略

增强做市策略是在**通用做市策略**基础上的智能化升级。如果说通用策略是"按固定规则摆摊"，增强策略则是"带大脑的摊贩"——它能感知市场环境变化，自动调整摆摊策略，在风险可控的前提下追求更优的做市效果。

**核心升级点：**
- **从被动定价到主动感知**：新增档位报价策略，直接锚定市场真实流动性
- **从固定规则到条件响应**：引入条件单系统，实现"如果…就…"的智能化决策
- **从逐笔对冲到批量对冲**：支持净敞口累积后统一对冲，降低交易成本
- **从简单风控到多维监控**：价格笼子、数量笼子、报单控制、行情响应四层防护

### 1.2 设计哲学

| 原则 | 具体体现 |
|------|---------|
| **市场跟随而非市场预测** | 档位报价锚定盘口，不试图预测方向 |
| **风险优先于收益** | 多层笼子+条件暂停，极端行情先保命 |
| **灵活性与纪律性平衡** | 条件单提供灵活响应，但执行逻辑严格固化 |
| **技术鲁棒性** | 行情乱序处理、废单重试、撤废响应，应对真实交易环境的混乱 |

## 第二章 双轨定价体系：两种基准价方法论

### 2.1 跟盘报价策略：公式化主动定价

**思想**：通过数学公式自主计算"理论公允价"，在此基础上加减偏移量形成买卖报价。

**实现路径：**

```
输入因子（P/A/B）→ 公式运算 → 基准价 → ±偏移量 → 各档报价
```

**基准价模式选择：**

| 模式 | 适用场景 | 公式示例 |
|------|---------|---------|
| **单基准价** | 买卖价差对称，市场平稳 | 买卖共用 `(最新价+买一+卖一)/3` |
| **双基准价** | 买卖非对称，或市场有方向性倾斜 | 买基准=`最新价-0.02`，卖基准=`最新价+0.03` |

**公式编辑器能力边界：**
- 因子：P（标的价格，可选最新价/昨结算/买一到五/卖一到五）、A/B（其他合约价格）
- 运算：`+ - * / % ( )`
- 函数：`min` `max` `avg` `sum` `round` `log` `log10`

> **设计意图**：单基准价简化管理，双基准价允许对买卖方向分别优化，适应非对称市场结构。

---

### 2.2 档位报价策略：市场化被动定价

**思想**：不自己算价格，而是**找到市场上其他做市商的真实挂单位置**，跟随定价。这是"打不过就加入"的务实策略。

**三种档位寻找模式：**

#### ① 中间价档位

**方法**：取盘口挂单位置的**几何中间档**作为基准。

```
买盘5档：98, 99, 100, 101, 102
中间档 = 第3档 = 100 → 买基准价 = 100

卖盘5档：103, 104, 105, 106, 107  
中间档 = 第3档 = 105 → 卖基准价 = 105
```

**偶数档圆整处理**（关键细节）：
- 4档价格：1.01, 1.02, 1.03, 1.04
- 中间两档均值 = (1.02+1.03)/2 = 1.025
- **买方向**：向上圆整 → 1.03（确保能买到）
- **卖方向**：向下圆整 → 1.02（确保能卖出）

> **圆整哲学**：买方向向上圆整是为了满足"买义务"（交易所对做市商有最低买量要求），卖方向向下圆整是为了满足"卖义务"。宁可牺牲一点价差，也要确保义务达标。

#### ② 中间量档位

**方法**：计算盘口挂单量的**平均值**，找到对应量所在的档位价格。

```
买盘挂单量：100, 200, 300, 400, 500（累计：100,300,600,1000,1500）
平均量 = 总挂单量/档位数 = 1500/5 = 300
达到300的档位 = 第3档（累计600）→ 买基准价 = 第3档价格
```

> **适用场景**：市场深度分布不均匀时，中间量比中间价更能反映"真实流动性重心"。

#### ③ 自定义档位量

**方法**：用户设定一个**累计挂单量阈值**，找到达到该阈值时的档位价格。

```
设定阈值：5000股
买盘累计：3000(档1), 8000(档2), 12000(档3)...
达到5000在档1和档2之间 → 取档2价格作为基准
```

> **设计意图**：让做市商可以精确控制"跟随深度"。阈值设小（如1000），跟随浅层流动性，报价更激进；阈值设大（如50000），跟随深层流动性，报价更保守。

---

### 2.3 档位报价的关键辅助机制

#### 剔除本方报价

**问题**：如果不剔除，自己的挂单会被计入市场档位，导致"自己跟自己玩"——按自己的买一计算基准价，然后报价永远追着自己的尾巴跑。

**实现**：计算档位前，先从市场数据中**扣除本方所有挂单量**，再重新排序计算。

| 档位 | 市场量 | 本方量 | 剔除后市场量 | 策略认定的档位 |
|------|--------|--------|-------------|---------------|
| 1 | 5000 | 5000 | 0 | **剔除** |
| 2 | 5000 | 4000 | 1000 | 策略认为的1档 |
| 3 | 4000 | 4000 | 0 | **剔除** |
| 4 | 4000 | 0 | 4000 | 策略认为的2档 |
| 5 | 5000 | 4000 | 1000 | 策略认为的3档 |

#### 档位不存在时递延计算

**问题**：小合约、非主力合约行情不活跃，可能5档都凑不齐。

**递延顺序**：5档 → 4档 → 3档 → 2档 → 1档 → 对方1档 → 最新价 → 昨收

> **底线**：如果连昨收都获取不到，策略停止。这是防止在完全无数据环境下盲报。

## 第三章 条件单系统：策略的"大脑"

### 3.1 设计公式：`策略 = 条件 + 操作`

这是增强策略区别于通用策略的**核心智能化模块**。通用策略是"一套参数跑到底"，增强策略是"根据市场状态自动换档"。

### 3.2 条件的构成：`条件 = 因子 + 逻辑`

#### 因子库（可扩展）

| 因子类型 | 具体因子 | 说明 |
|---------|---------|------|
| 时间因子 | 当前时间 | 可与HHMMSS格式对比，如`时间>093000` |
| 盘口因子 | 盘口价差、买一、卖一、盘口价格 | 市场微观结构 |
| 价格因子 | 最新价、买卖基准价 | 行情状态 |
| 衍生因子 | 涨跌幅 | `(最新价/昨收-1)` 或 `(昨收/最新价-1)` 的绝对值 |

> **扩展性**：后续支持因子平台，客户可用Python编写自定义因子接入。

#### 逻辑运算

```
逻辑表达式：A/B-1>0.03
含义：(因子A/因子B-1) > 3%

支持运算符：> < = >= <= & | ( )
& = 并且，| = 或者
```

**配置示例：**

| 条件名称 | 逻辑表达式 | 含义 |
|---------|-----------|------|
| 基准价差>0.5 | `基准价差>0.5` | 买卖基准价差距过大，市场可能失衡 |
| 盘口价差>0.2 | `盘口价差>0.2` | 买卖盘口红利丰厚，可积极做市 |
| 涨跌幅>3% | `A/B-1>0.03`（A=最新价，B=昨收盘） | 价格剧烈波动，需避险 |

### 3.3 三种操作响应

#### ① 额外偏移：在原有报价上"再加一层"

**触发逻辑**：满足条件时，在**原有基准价+偏移量计算出的委托价**基础上，再进行一次额外偏移。

```
原买委托价 = 买基准价 + 买偏移量
条件触发后：新买委托价 = 原买委托价 + 额外买偏移

效果示例：
- 原买偏移 = -0.05（向下5跳）
- 额外偏移 = -0.02（再向下2跳）
- 最终买价 = 基准价 - 0.07（更保守，更难被成交）
```

**应用场景**：
- 市场波动加大时，**主动拉大价差**，减少被"扫单"的风险
- 买卖偏移可设正负值：同向偏移（都往下或都往上）实现整体平移，反向偏移实现**缩窄或扩大价差**

#### ② 重设报价：完全切换报价方案

**触发逻辑**：满足条件时，**整套报价参数被替换**为预设的另一套方案。

**可重设内容**：
- 基准价（单/双基准价模式、具体公式）
- 档位（买/卖各几档、每档偏移量）
- 数量（每档买入/卖出数量）
- 拆单笔数
- 容忍度
- 开平方向

> **应用场景**：开盘前用保守方案，开盘后根据开盘波动切换激进或防御方案；或主力合约换月时切换参数。

#### ③ 暂停报价：紧急刹车

**触发逻辑**：满足条件时，**撤回所有当前委托**，在设定时间内**不再报新单**，但策略保持运行监控状态。

```
暂停报价时间：60秒
行为：撤单 → 等待60秒 → 60秒后自动恢复报价
```

> **应用场景**：重大数据发布前、价格剧烈波动时、或检测到异常交易模式时的主动避险。

### 3.4 条件优先级与执行纪律

**规则1：顺序优先**
- 多个条件按**列表顺序**依次判断
- **一旦满足一个条件，立即执行对应操作，后续条件不再判断**
- 支持**上下拖拽改变条件顺序**

**规则2：不可并行**
- 同一时刻只能执行一种操作
- 不存在"同时额外偏移又重设报价"的情况

> **设计意图**：避免条件冲突导致的逻辑混乱。用户需通过**优先级排序**表达策略偏好——把最重要的条件放前面。

## 第四章 报价更新机制：条件与容忍度的协同

### 4.1 每轮决策流程

```
┌─────────────────────────────────────────┐
│  新一轮行情到达                         │
└─────────────────────────────────────────┘
                    │
                    ▼
        ┌─────────────────────┐
        │ 检查条件单是否满足？  │
        └─────────────────────┘
           │              │
        满足│              │不满足
           ▼              ▼
    ┌────────────┐   ┌─────────────────┐
    │ 执行条件操作 │   │ 检查基础容忍度   │
    │ (额外偏移/   │   │ 各档位价格 vs    │
    │  重设/暂停)  │   │ 当前挂单价格     │
    └────────────┘   └─────────────────┘
                          │
                       触发│  未触发
                          ▼     ▼
                    ┌────────┐ ┌────────┐
                    │更新报价│ │维持现状│
                    └────────┘ └────────┘
```

### 4.2 容忍度更新的细节

**判断标准**：
- 仅比较**价格**和**数量**
- **不考虑开平方向**（买开仓和买平仓视为同一档位）
- **不支持跨档匹配**（买1档只和买1档比，不和买2档比）

**触发后行为**：
- 仅更新**触发容忍度的该档位**
- 其他档位维持不变（Order模式）或联动更新（Quote模式）

## 第五章 部成处理：精细化成交管理

### 5.1 部成的两种场景

| 场景 | 策略选择 | 行为 | 适用心态 |
|------|---------|------|---------|
| **部分成交** | **不想成交** | 立即撤销该档位剩余挂单，可设N秒内不再报单 | "这单是被偷袭的，剩下的不卖了" |
| | **想成交** | 剩余挂单维持不动，继续等待成交 | "正好想出货，继续挂着" |
| **全部成交** | 统一处理 | 继续判断条件单/容忍度，决定是否更新报价 | "这一档完了，看要不要补货" |

### 5.2 "不想成交"的战术意图

**典型场景**：你的卖1档被对手吃掉一部分，但你觉得价格还会涨，不想继续在这个价位卖出。

**操作**：部成响应设为"立即撤余单+5秒内不再报单"——撤掉剩下的，等价格涨上去再重新挂更高价位。

## 第六章 对冲策略：从逐笔到净敞口

### 6.1 设计思想演变

| 版本 | 对冲触发 | 优势 | 劣势 |
|------|---------|------|------|
| 通用策略 | **逐笔成交即对冲** | 实时中性，风险最低 | 交易成本高，频繁小额对冲 |
| 增强策略 | **净敞口累积后对冲** | 减少对冲次数，降低冲击成本 | 累积期间有敞口暴露 |

**增强策略的折中方案**：通过**定时器对冲**或**阈值触发**，在"实时中性"和"成本控制"之间取得平衡。

### 6.2 对冲触发机制

#### 阈值触发

```
买入对冲触发：净买入量 ≥ 设定阈值  或  净买入额 ≥ 设定阈值
卖出对冲触发：净卖出量 ≥ 设定阈值  或  净卖出额 ≥ 设定阈值
```

**阈值设为0的含义**：只要有净买入/卖出成交就触发对冲，退化为通用策略的逐笔模式。

#### 定时器对冲

**机制**：按秒采集净成交量/额，达到阈值时统一对冲。

```
示例：
- 设定：每5秒检查一次
- 5秒内净买入累计：12手
- 阈值：10手
- 触发：12手 ≥ 10手 → 发出买入对冲委托
```

> **优势**：将多笔小成交合并为一笔大单对冲，减少市场冲击，可能获得更好价格。

### 6.3 对冲委托数量计算

#### 量模式

```
买入对冲委托数量 = 净买入量 / 对冲系数 / 报单价格
卖出对冲委托数量 = 净卖出量 / 对冲系数 / 报单价格
```

#### 额模式

```
买入对冲委托数量 = 净买入额 / 对冲系数 / 合约乘数 / 报单价格
卖出对冲委托数量 = 净卖出额 / 对冲系数 / 合约乘数 / 报单价格
```

**对冲系数的作用**：

| 场景 | 对冲系数设置 | 计算结果 |
|------|------------|---------|
| 同合约100%对冲 | 1.0 | 净买入10手 → 对冲10手 |
| 同合约50%对冲 | 2.0 | 净买入10手 → 对冲5手（保留部分敞口） |
| 跨合约对冲（TL→TS） | 根据合约价值比 | 净买入TS 10手 → 对冲TL 3手（假设TL价值≈3倍TS） |

> **设计意图**：对冲系数是**风险暴露的调节阀**。系数=1完全中性，系数>1部分敞口，系数<1超额对冲（反向投机）。

### 6.4 撤补机制与最终失败处理

| 阶段 | 行为 | 选项 |
|------|------|------|
| **首次委托** | 按计算价格发对冲单 | — |
| **未成交** | 达到撤补间隔 → 撤单并按最新行情重算价格重报 | 撤补次数内循环 |
| **撤补耗尽** | 最终失败处理 | **回补**：撤单数量加回对冲累计成交量，下次重新对冲<br>**不回补**：忽略该笔，需手动对冲 |

> **回补 vs 不回补**：回补是"这单没成，记账时当作没对冲过，下次继续尝试"；不回补是"这单算了，人手工处理"。

## 第七章 风控体系：四层笼子

### 7.1 价格笼子：防止报价离谱

**机制**：报价必须在基准价±偏移量的"笼子"内，超出则**撤单暂停**，持续监控，满足条件后**自动恢复**。

```
按价格模式：笼子边界 = 基准价 ± 偏移量（跳）
按比例模式：笼子边界 = 基准价 × (1 ± 偏移%)
```

**与条件单暂停的区别**：
- 价格笼子：报价计算出错或市场极端波动时的**被动防护**
- 条件单暂停：基于预判的**主动避险**

### 7.2 数量笼子：防止过量交易

**监控维度矩阵：**

| 维度 | 控制对象 | 范围选择 | 触发行为 |
|------|---------|---------|---------|
| **成交量** | 净买量 / 净卖量 | 当次/当日策略/当日全部 | 策略停止 |
| **成交额** | 净买额 / 净卖额 | 同上 | 策略停止 |
| **持仓数量** | 当前持仓上下限 | 实时 | 策略停止 |
| **持仓金额** | 当前持仓金额上下限 | 实时 | 策略停止 |

**范围选择的含义：**
- **当次策略**：本次启动后累计（不含之前暂停的）
- **当日策略**：当日所有本策略启动的累计（含之前暂停后重启的）
- **当日全部**：策略+手工交易的总和

> **设计意图**：防止"策略失控+人工误操作"的双重风险。

### 7.3 报单控制：时间维度风控

**阈值字段**（一段时间内的统计）：

| 字段 | 含义 | 应用场景 |
|------|------|---------|
| 报单数量/金额 | 过于频繁报单 | 防止策略进入"高频震荡" |
| 成交数量/金额 | 成交过于集中 | 防止被大单"秒杀" |
| 标的涨跌幅绝对值 | 价格波动剧烈 | 自动暂停避险 |
| 新增净持仓数量 | 敞口累积过快 | 防止对冲失效 |
| 单边成交数量 | 买卖严重失衡 | 防止市场单边行情中被持续扫单 |

**涨跌幅绝对值计算**（防方向误判）：

```
找最低价p1（时间t1）和最高价p2（时间t2）

如果 t2 > t1（后涨到高）：
    涨跌幅 = p2/p1 - 1
    
如果 t2 < t1（先涨后跌）：
    涨跌幅 = |p1/p2 - 1|  （取绝对值，不区分涨跌方向）
```

> **关键**：用**绝对值**不区分涨跌，只关心波动幅度。暴涨和暴跌同等对待。

### 7.4 跟盘交易设置：技术鲁棒性

#### 自动开平底仓设置

**思想**：保留一定底仓，避免频繁开平切换。

```
多单底仓设为5手：
- 当前多头可用 ≤ 5手 → 新买单一律"开仓"（建立底仓）
- 当前多头可用 > 5手 → 启动自动开平（有持仓先平，不足再开）
```

#### 全撤再报模式

**问题**：行情快速变化时，撤单和报单可能交叉，导致重复挂单。

**解决**：先发起撤单，等待**所有撤单消息都到达终态**（确认已撤），再执行新报单。

> **代价**：增加一个往返延迟；**收益**：杜绝重复挂单风险。

#### 行情响应机制

**问题本质**：委托和行情消息可能**乱序**——先收到成交消息，后收到行情消息。

**乱序场景：**
```
正常顺序：行情消息 → 成交消息 → 行情消息
乱序情况：成交消息先到，但对应行情未到
后果：策略以为委托仍在盘中，实际已成交
```

**解决**：执行行情响应后，重新根据**当前委托表 + 最近一次行情信息**计算本方量，校正委托状态。

```
行情响应后：
1. 用最新行情重新计算"本方应该在各档位挂多少"
2. 对比实际委托表
3. 差异部分 = 需要补报或撤单的部分
4. 触发委托/撤单操作
```

> **无行情响应的风险**：行情不活跃时，委托状态可能长期错误，导致该撤不撤、该报不报。

## 第八章 通用设置：策略协同

### 8.1 优先级设置：防自成交

**问题**：多个策略或手工单在同一价位反向报单，导致**自己和自己成交**。

**规则**：
- 手工单 = 最高优先级（不可被策略挤掉）
- 策略单可设优先级
- 同价位反向时：**优先级高的挂单，优先级低的不挂单等待**

**支持模式**：
- **对冲优先**：对冲单优先于跟盘单
- **跟盘优先**：跟盘单优先于对冲单

### 8.2 暂停停止处理：防止"僵尸策略"

```
策略暂停后 n 秒未能自动恢复 → 自动停止
```

**应用场景**：风控触发暂停后，如果长时间不满足恢复条件（如价格笼子长期超限），策略不会无限期挂起，而是彻底停止，等待人工检查。

### 8.3 自成交检查

- **默认**：策略内部校验自成交，发现潜在自成交时调整报价或暂停
- **勾选取消**：不校验自成交（需用户自行承担风险，或确信不会有冲突）

## 第九章 完整交易生命周期示例

### 场景设定
- 合约：TS2403
- 定价：档位报价策略，自定义档位量=5000，中间价模式
- 条件单：涨跌幅>2% → 暂停报价60秒
- 对冲：净买入量阈值=10手，对冲系数=1.0，定时器5秒
- 风控：价格笼子±0.05，数量笼子净买量≤50手

### 时间线

| 时间 | 事件 | 策略响应 |
|------|------|---------|
| T+0 | 策略启动 | 读取盘口，剔除本方报价，计算档位基准价，铺5档买卖单 |
| T+1s | 买1档成交3手 | 净买入量=3，未达阈值，不对冲；部成响应="想成交"，维持余单 |
| T+3s | 买2档成交5手 | 净买入量=8，未达阈值，不对冲 |
| T+5s | 定时器检查 | 净买入量=8 < 10，不触发对冲 |
| T+6s | 买1档又成交4手 | 净买入量=12，但定时器刚检查过，等下次 |
| T+10s | 定时器检查 | 净买入量=12 ≥ 10，触发买入对冲，卖出12手对冲合约 |
| T+15s | 市场突发利好，涨跌幅达2.5% | 条件单满足 → 暂停报价60秒，撤掉所有做市委托 |
| T+75s | 60秒暂停结束 | 检查价格笼子（当前价在笼内）→ 恢复报价，重新铺档 |
| T+80s | 净买入量累计达55手 | 数量笼子触发 → 策略停止，需人工重启 |

## 第十章 设计思想总结

| 思想 | 实现机制 | 价值 |
|------|---------|------|
| **市场感知** | 档位报价策略 + 条件单因子 | 从"盲人摸象"到"看清市场结构" |
| **动态响应** | 条件单三种操作 + 优先级排序 | 从"一成不变"到"因势而动" |
| **成本优化** | 净敞口累积对冲 + 定时器 + 对冲系数 | 从"每笔必冲"到"批量精算" |
| **风险分层** | 价格笼子/数量笼子/报单控制/行情响应 | 从"单点防护"到"纵深防御" |
| **技术鲁棒** | 全撤再报/行情响应/撤废重试/废单处理 | 从"理想环境"到"真实战场" |
| **人机协同** | 暂停恢复/超时停止/自成交检查/优先级 | 从"全自动黑箱"到"可控可介入" |

---

增强做市策略的本质，是在通用策略的"纪律性"基础上，增加了"环境感知"和"智能决策"两层能力。它不要求预测市场方向，但要求**理解市场结构、识别自身状态、在风险边界内灵活调整**——这正是成熟做市商从"机械执行"走向"智能执行"的必经之路。
